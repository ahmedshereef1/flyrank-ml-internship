WHAT WAS CUT FROM THE SPEC (and why)
---

Cut: Automatic GitHub file reading
  Spec said: Claude Project would read .ipynb files directly.
  Reality: Claude Projects on the free plan do not have file connectors or MCP
  servers. The "live file connection" is the session starter template — a structured
  text file the user pastes at the start of each session. This is a real file
  containing real data from the repo; it satisfies the "live data connection"
  requirement even though it's paste-in rather than automated.
  Documented because: this is the main deviation from the spec. The spec said
  "no file system access needed" — that was accurate, but the framing was about
  not needing automation, not about not having the capability. The template file
  approach is actually better for this use case: it forces me to consciously
  review my numbers before pasting, which is part of the value.

Cut: Automatic session scheduling
  Spec said: agent runs manually 3-4 times per week.
  Reality: still true, no change needed. Nothing to cut here — the spec was already
  correct on this point.

Not cut: All 5 eval cases
  All 5 pass with the final instruction set. No eval case was dropped.

---
LIVE TOOL / DATA CONNECTION — HOW IT'S IMPLEMENTED
---

The "live file connection" in this build is the session starter template file
(FL-07_session_starter_template.txt). Each session:

1. I open my most recent notebook in Jupyter/VS Code.
2. I copy the actual output numbers from the notebook's last run cell.
3. I paste them into the template fields.
4. I paste the filled template as the first message to the Claude Project.

The agent reads real numbers from a real file I maintain in the repo. It is not
automated, but it is a structured data source — not free-form chat. The template
enforces a schema: model name, metric values, base rate, top features. This schema
is what allows the sanity rules to fire reliably.

This is the documented deviation: "live file connection" implemented as structured
paste-in rather than MCP filesystem connector.

---
WHAT DOESN'T WORK (known limitations)
---
  - The agent cannot read my notebooks directly. It depends on me copying numbers
    accurately. If I paste a wrong number, it sanity-checks the wrong number.
  - Session state note is only as good as what I tell it at the end of the session.
    If I forget to paste the end-of-session message, there's no automatic record.
  - Claude Project conversation history has a context window limit. After many
    sessions, older state notes will scroll out of context. Mitigation: keep the
    session state note format short (3 lines) so it fits efficiently.
